# KBO 투구 제구 성공 확률 예측 (LG Aimers 9기)

LG Aimers 9기 DACON 해커톤 "KBO 투구 제구 예측" 참가 기록입니다. 최종 순위는 참가자
2,403명 중 97위, 리더보드 최고 점수는 1146.91입니다.

대회 3주 동안 시도한 것들과 그 결과를 시기순으로 정리했습니다. 통한 것보다 통하지 않은
것이 훨씬 많았고, 방향을 바꾼 이유가 대부분 거기서 나왔습니다.

## 대회 소개

투구 한 개가 제구에 성공했는지(`control_success`)를 확률로 예측하는 문제입니다. 입력으로는
그 공을 던지기 전까지 알 수 있는 정보만 쓸 수 있습니다. 볼카운트, 주자, 점수 상황, 투수와
타자의 누적 기록 같은 것들이고, 실제 투구 위치나 판정 결과는 사용할 수 없습니다.

학습 데이터는 2019-2024 시즌 약 147만 구이고, 평가는 공개되지 않은 2025 시즌 데이터로
진행됩니다. 점수는 Brier Skill Score에 10만을 곱한 값입니다. 제출은 추론 코드와 모델을
zip으로 올리면 서버가 실행하는 방식이었고, 평가 데이터의 각 행은 서로 독립적으로 예측해야
했습니다.

## 시도한 것들

### 1단계. 무엇을 보고 판단할지 정하기 (8월 10-12일)

먼저 검증 방식을 정했습니다. 2023년까지로 학습해 2024년을 예측하는 홀드아웃에 대회 기준
모델을 넣으니 492점, 실제 리더보드는 549점이었습니다. 이 정도면 홀드아웃을 보고 판단해도
되겠다고 봤습니다.

첫 제출(926점) 뒤에 알게 된 것은 점수가 모델보다 2025년 성공률 추정에 크게 좌우된다는
점이었습니다. 시즌 성공률의 하락폭이 −0.029, −0.014로 줄어드는 중이었는데 같은 폭으로 계속
떨어진다고 가정했고, 이 오차만으로 20점 넘게 잃었습니다.

판별력을 올릴 방법을 찾다가 통산 성공률의 문제를 발견했습니다. 이 값은 경력 전체의 누적인데
그 기간에 리그 평균이 0.565에서 0.486까지 내려갔습니다. 경력이 긴 투수일수록 성공률이 높던
시절 기록이 많이 섞여 실제보다 좋아 보입니다. 투수별 시즌 투구 수로 경력 기간의 리그 기대치를
계산해 빼주니 2024년 검증이 46.5점, 2023년 검증이 177.5점 올랐습니다. 같은 방식으로 시즌별
리그 수준을 복원해 보니 성공률 하락의 주원인은 포수 요구와 반대로 던지는 실패가 0.18에서
0.26으로 늘어난 것이었습니다.

이어서 실패 유형과 상황을 조합한 피처를 넣었습니다. 3볼에서는 가운데로 몰리는 실패가,
2스트라이크에서는 크게 벗어나는 실패가 더 위험합니다. 성공률이 같은 두 투수라도 실패하는
방식이 다르면 같은 상황에서 위험도가 반대가 됩니다. 성공률×상황은 −2.8이었지만 실패 유형
비율×상황은 +11.4였습니다. 해로운 컬럼도 걸러냈는데, 학습 중 중요도가 아니라 다음 시즌
데이터로 잰 순열 중요도를 기준으로 18개를 뺐습니다.

해보고 접은 것: 모델 계열 바꾸기(XGBoost, DART, ExtraTrees 등, 기여 0), AutoGluon(747.5로
기존 913.8보다 한참 낮음), 시간 기반 스태킹(−73에서 −228), 최근 시즌 가중 7가지(전부 음수),
부분집단별 보정(같은 데이터에서 +26.5였지만 다음 시즌으로는 +3.6).

### 2단계. 투수를 숫자 하나가 아니라 여러 상황의 모습으로 (8월 13-21일)

운영진 질의응답에서 학습 데이터 안에서는 같은 투수의 이후 행을 참고해 학습 목표를 세분화해도
된다는 답을 받았습니다. 누적 비율 컬럼을 투수별 투구 순서대로 차분하면 투구마다 실패 유형을
복원할 수 있어서, 이 라벨로 새 피처를 만들 수 있게 됐습니다.

먼저 어디서 점수를 잃는지 진단했습니다. 같은 피처로 2024년 안에서 교차검증하면 판별력이
30.3인데 2023년까지로 학습해 2024년을 예측하면 21.6으로 떨어졌습니다. 정보원별로 나눠 보니
판별력의 84%가 "투수가 누구인가"에서 나왔습니다.

이걸 투수 실력을 더 정밀하게 추정하라는 뜻으로 읽고 세 가지를 시도했지만 전부 실패했습니다.
MARCEL 방식 투영 +1.7, 경험적 베이즈 갱신 −5.2, 학습된 투영 −151.9였습니다. 기존 피처가
실력 추정은 이미 충분히 담고 있었습니다.

효과가 있었던 건 투수를 여러 상황별 수치로 설명하는 조건부 프로파일이었습니다. "3볼일 때
가운데로 몰리는 비율", "좌타자 상대로 크게 벗어나는 비율" 같은 값들입니다. 첫 시도는 같은
행의 정답이 통계에 섞여 −404로 무너졌고, 각 행에는 그 행의 시즌보다 이전 시즌의 통계만
붙이도록 고쳐 +49.3을 얻었습니다. 투수 팀과 타자 팀 기준을 더해 +52.7까지 올렸습니다.

피처가 210개로 늘자 1단계에서 기여가 0이던 CatBoost(+3.3)와 RealMLP(+2.3)가 앙상블에 보탬이
되기 시작했습니다. 한 번 기각한 방법도 조건이 바뀌면 다시 확인해야 한다는 걸 이때 배웠습니다.
순열 중요도로 가지치기를 두 번 반복해 210개를 123개로 줄이니 LightGBM이 27.8점 올랐는데, 같은
가지치기가 RealMLP에는 −74.3이어서 트리 모델만 줄인 피처를 쓰게 했습니다.

이 모델들을 10개로 섞은 판이 1065.15점이었습니다. 직전 제출은 검증 점수가 비슷한데 991.73점
이었고, 나중에 보니 모델 문제가 아니라 평균 보정값이 0.0128 어긋나 있었습니다.

해보고 접은 것: 구장별 조건부(−10.8), 투수×구장(+0.1), 투수 시즌 내 변동성(−4.1), 조회 기준을
더 늘리기(투수팀×타자팀 975.9, 전부 넣기 963.5, 타자 개인 −9.2).

### 3단계. 검증에서 좋았던 것이 제출에서 사라짐 (8월 22-26일)

두 가지를 더 올렸습니다. 하나는 투수의 이번 시즌 성적을 시즌 전 추정치와 표본 수에 비례해
섞는 베이지안 갱신, 다른 하나는 TrackMan 투구 로그를 투수 단위로 집계한 피처였습니다. 둘 다
2024년 홀드아웃에서 20번 반분 검증을 모두 통과했는데, 제출해 보니 TrackMan을 넣은 쪽은
1054.65점으로 오히려 낮았고 베이지안 갱신만 넣은 쪽은 1065.18점으로 차이가 없었습니다.

원인은 TrackMan 집계표를 2019-2024년 전체로 만들어 두고 2024년 검증에 그대로 쓴 것이었습니다.
검증할 시즌의 정보가 피처에 들어가 있었습니다. 2023년까지로만 다시 만들자 +6.4였던 효과가
−23.7로 뒤집혔습니다. 컬럼을 줄인 판(−15.8)과 갱신 강도만 조절한 판(−5.6)도 마찬가지였습니다.

같은 시기에 볼카운트나 상대 팀별로 이번 시즌 성적을 갱신하는 변형이 검증에서 +43.9에서
+95.6까지 나왔습니다. 이 프로젝트에서 본 가장 큰 수치였는데, 추론할 때 평가 데이터의 다른
행을 시간순으로 누적해야 만들 수 있는 피처라 규정 위반으로 판단해 쓰지 않았습니다.

TrackMan 측정값을 교사 신호로 쓰는 방향도 정리했습니다. 학습 데이터에서 투구별 물리량을
붙이면 +423.3의 가치가 있었지만, 그 가치가 전부 투수의 평소 수준 대비 그 투구의 편차에서
나왔습니다. 아직 던지지 않은 공의 편차는 사전에 알 수 없어서 증류(−3.8에서 −7.9)로도
주변화(−10.9)로도 옮겨오지 못했습니다.

이 시기의 결론은 2024년 한 시즌만 보는 검증을 더는 믿을 수 없다는 것이었습니다.

### 4단계. 검증 방식을 바꾸고 단순한 구성으로 (8월 26-28일)

검증을 2022, 2023, 2024년 세 시즌에 대해 각각 그 이전 시즌으로 학습해 예측하는 방식으로
바꿨습니다. 그리고 팀원이 만든 단일 CatBoost 구성(피처 64개)을 같은 검증 체계에서 재현해
비교했습니다.

결과가 분명했습니다. 우리 피처는 2024년에서는 104.6점 높았지만 퓨처스 경기 성격이 급변한
2023년에서는 445.8점 낮았습니다. 우리에게 가장 유리한 시즌 하나로만 판단해 온 셈이었습니다.
또 모델 계열만 바꾼 예측끼리는 상관이 0.94-0.98이었는데, 피처를 만드는 방식이 다른 예측과는
0.85-0.90이었습니다. 앙상블에 다양성이 없다고 결론 냈던 원인이 모델이 아니라 피처 쪽에
있었습니다.

단순한 구성에 평균 보정만 얹어 제출하니 1062점이 나왔습니다. 모델 10개와 피처 123개, 시드
8개로 만든 155MB 앙상블(1065)과 3점 차이였습니다. 여기서 기반을 단일 CatBoost로 바꾸기로
했습니다.

### 5단계. 오류의 종류별로 나눠서 고치기 (8월 28-30일)

퓨처스(2군) 경기의 제구 성공률이 2022년 0.71에서 2023년 0.47로 무너진 것을 확인했습니다. 같은
투수가 퓨처스와 정규리그에서 던진 성공률 차이도 +0.248에서 +0.023으로 줄어서, 선수 구성보다는
기록 방식이 바뀐 것으로 봤습니다. 퓨처스 경기를 학습에서 빼면 세 검증 시즌 중 두 시즌이
나빠졌고, 빼지 않고 2023년 전후를 구분해 주면 세 시즌 모두 좋아졌습니다. 인코딩 8가지를
비교해 정규리그 / 2022년까지 퓨처스 / 2023년 이후 퓨처스의 세 범주로 나눴습니다.

잔차 보정도 만들었습니다. 학습 시즌의 검증 예측에서 잔차를 구해 투수·상황별로 평균낸 표를
만들어 두고, 추론할 때 각 행이 자기 키로 찾아 더하는 방식입니다. 시즌마다 잔차 평균을 빼서
시즌 전체 수준은 평균 보정이 맡게 하고, 기준을 네 개(투수×타자 손, 볼카운트, 투수×볼카운트,
주자 상태)로 두고, 표본이 적은 칸을 줄이는 강도를 찾았습니다.

이 둘을 반영한 제출이 1102점이었습니다. 판별력을 올리는 피처, 체제 변화를 알려주는 재코딩,
잔차 보정이 각각 다른 종류의 오류를 고친다는 것도 이때 확인했습니다.

해보고 접은 것: 투수·타자 매치업 피처는 검증에서 +33이었지만 리더보드에서는 +5(1067.16)에
그쳤습니다.

### 6단계. 무엇이 다음 시즌으로 넘어가는지 가려내기 (8월 30-31일)

조건부 통계를 다시 설계했습니다. 막연한 조합 대신 0볼 0스트라이크부터 풀카운트까지 볼카운트별로,
그리고 타자 손별로 상황을 명확히 나눴습니다. 16개를 더한 판은 2024년 검증이 41.5점, 28개와
5클래스 분류를 더한 판은 90.6점 올랐지만 리더보드는 각각 1096.51점과 1096점으로 조금
낮았습니다.

그래서 리더보드 점수 차이를 얼마나 믿을 수 있는지 쟀습니다. 2024년 데이터를 평가셋처럼 두고
부트스트랩으로 두 모델의 점수 차이를 재니 표준오차가 약 13점이었습니다. −6점은 해로웠다기보다
효과가 없었다고 봐야 합니다. 다만 두 번 연속 같은 자리에 떨어졌으니 +40에서 +90 규모의 효과는
없다고 결론 내렸습니다. 한 시즌 안에서 뚜렷해 보이는 세부 패턴이 다음 시즌까지 유지되지
않았습니다.

검증의 함정도 하나 더 찾았습니다. 퓨처스 재코딩은 2023년 검증에서 +902로 보였는데 2024년
검증에서는 +5였습니다. 2022년까지의 학습 데이터에는 "2023년 이후 퓨처스" 범주가 아예 없어서,
모델이 처음 보는 범주를 평균 근처로 예측한 것이 개선처럼 보인 것입니다. 이후로는 체제 관련
피처를 2024년 검증으로만 판단했습니다.

조건부 통계를 빼고 5클래스 분류 블렌드, 확률 클리핑, 시드 앙상블만 남기니 1108.81점이었습니다.
5클래스 분류는 조건부 통계와 함께 쓸 때 섞는 비율 0.30이 최적이었는데, 조건부 통계를 빼니
0.75로 올라가며 효과가 두 배가 됐습니다. 둘이 같은 정보를 두고 겹치고 있었습니다.

마지막으로 팀 단위 체제 변화를 확인했습니다. 팀 13은 퓨처스 경기 비율이 38.1%로 다른
팀(3-10%)보다 훨씬 높았고, 이 팀이 관여한 경기의 리그 대비 성공률 차이가 2021년 개막과 2023년
5월에 뚜렷하게 바뀌었습니다. "팀13 경기인지"와 "2023년 5월 이후인지"를 곱한 피처를 넣으니
2024년 검증이 33.7점 올랐고, 다른 팀까지 넓히면 오히려 낮아졌습니다. 기반 모델이 바뀐 만큼
잔차 보정 설정을 다시 찾고, 8월 31일 주최측 안내에 따라 평균 보정값도 학습 데이터만으로 다시
계산했습니다. 이렇게 만든 제출은 검증에서 오른 42.3점이 리더보드에서 38.1점으로 이어져
1146.91점을 받았습니다.

## 최종 모델

```
입력      그 투구 이전에 알 수 있는 정보만 사용
          기본 피처 64개: 공식 누적 기록과 경기 상황 47개, 행 단위로 복원한 이번 시즌 기록 17개
          경기유형 재코딩: 정규리그 / 2022년까지 퓨처스 / 2023년 이후 퓨처스
          팀13 체제 지시자 2개

모델      CatBoost 회귀 3개, CatBoost 5클래스 분류 2개 (시드만 다름)
          로짓 공간에서 0.25 : 0.75로 섞은 뒤 확률을 0.38~0.70으로 자름

잔차 보정  정규리그 경기만. 투수×타자 손, 볼카운트, 투수×볼카운트, 주자 상태 기준의
          동결표를 각 행이 자기 키로 조회해 더함

평균 보정  train.csv로 추정한 2025년 성공률 0.48051에 맞춰 로짓에 상수 하나를 더함
```

이번 시즌 기록은 학습이 끝난 시점의 누적값을 저장해 두고 각 행의 누적 기록에서 빼서
복원합니다. 5클래스 분류는 실패 유형(가운데로 몰림, 요구 반대, 크게 벗어남)을 나눠 학습한 뒤
성공 클래스의 확률만 씁니다. 평균 보정값은 시즌 성공률을 예측하는 규칙 13가지를 2021-2024년에
과거 데이터만으로 시험하고, 오차가 작았던 규칙에 더 큰 가중치를 줘서 합친 값입니다. 시즌
막바지 수준이 시즌 평균보다 다음 시즌을 더 잘 맞혔습니다.

## 돌아보며

### 검증 설계가 모델보다 중요했다

가장 오래 헤맨 이유는 2024년 한 시즌 검증을 믿은 것이었습니다. 그 결과 검증 시즌의 정보가
섞인 피처를 좋은 피처로 착각했고, 체제가 급변한 2023년에 약한 구성을 계속 쌓았습니다. 세 시즌
검증으로 바꾼 뒤에야 판단과 제출 결과가 맞아떨어지기 시작했습니다.

### 시즌을 넘어가는 개선은 따로 있었다

한 시즌 안의 세부 패턴을 담은 피처는 검증에서 +40에서 +90이 올라도 리더보드로 이어지지
않았습니다. 반대로 퓨처스 재코딩이나 팀13 지시자처럼 데이터가 만들어진 방식을 설명하는 피처,
그리고 학습 목표나 앙상블, 보정 쪽 개선은 검증에서 오른 만큼 대부분 리더보드에서도 올랐습니다.

### 복잡하게 쌓는 것보다 보정이었다

155MB 앙상블과 단일 CatBoost의 차이가 3점이었고, 점수가 크게 갈린 제출들은 대부분 평균 보정이나
누수에서 원인이 나왔습니다. 단순한 구성으로 바꾼 뒤 오히려 무엇이 효과가 있는지 가려내기가
쉬워졌습니다.

## 실행 방법

Python 3.11, CPU만 사용합니다. 시간은 12스레드 기준이고 메모리는 16GB 이상을 권장합니다.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

DACON 대회 페이지에서 받은 `train.csv`를 `data/` 폴더에 넣습니다. 대회 데이터는 재배포할 수
없어서 저장소에는 포함하지 않았습니다.

```bash
python derive_target.py     # 평균 보정값 계산 (약 30초, 0.48051 출력)
python train.py             # 전체 학습 (약 3시간), output/submit.zip 생성
```

`train.py`는 시간순 검증 예측(약 98분), 잔차 보정표 생성, 최종 모델 학습(약 71분), 평균 보정과
행 독립성 검사(약 5분)를 차례로 진행합니다. 검사에서 하나라도 어긋나면 zip을 만들지 않습니다.
`python train.py --fast`는 회귀와 분류 모델을 하나씩만 학습하며, 이전 실행의 잔차 보정표가
`output/`에 남아 있으면 재사용해 약 35분에 끝납니다.

## 폴더 구조

```
train.py             학습부터 제출 zip 생성까지
derive_target.py     평균 보정값 계산
submission/          제출 zip에 들어간 추론 코드
docs/experiments.md  단계별 세부 수치
```

`submission/`은 리더보드 1146.91점을 받은 제출 zip과 같은 코드라 주석도 당시 그대로 두었습니다.
`submission/requirements.txt`는 초반 LightGBM 계열부터 이어 쓰던 목록이라 지금 코드가 쓰지 않는
패키지도 들어 있습니다.

## 대회 규정

- 평가 데이터의 각 행을 독립적으로 예측합니다. 한 행씩 넣거나, 순서를 섞거나, 성질이 정반대인
  행들 사이에 끼워 넣는 등 25가지 방식으로 넣어도 결과가 완전히 같은 것을 확인했습니다.
- 평가 데이터 안에서 통계를 내거나 다른 행을 참고하지 않습니다. 잔차 보정표와 이번 시즌 기록의
  기준값은 모두 학습 데이터로 만들어 저장해 두고, 각 행이 자기 값으로만 조회합니다.
- 현재 투구의 위치, 판정, 구종, TrackMan 측정값은 쓰지 않습니다.
- 대회 초반에는 운영진 질의응답을 근거로 평균 보정값을 제출 점수에서 역산해 쓰기도 했습니다.
  8월 31일 보정 상수는 학습 데이터로 정하라는 안내가 나온 뒤로는 학습 데이터로만 계산했고,
  최종 제출본의 값도 그렇게 구한 것입니다.

대회는 2026년 9월 2일에 끝났습니다. 규정 8-A의 코드 공유 제한은 대회 기간에 한정되고, 8-B는
대회 정보를 바탕으로 만든 소스 코드의 공개를 허용합니다. 규정 7-B에 따라 대회 데이터와 주최측
데이터 설명서는 포함하지 않았습니다.

## 참고한 것

- 4단계의 단일 CatBoost 64피처 구성은 팀원이 만든 노트북 설계를 우리 검증 체계에서 다시
  구현한 것입니다.
- 잔차 보정은 팀원이 먼저 시도한 방식을 이어받아 다시 만들었습니다.
- 팀13 지시자는 대회 중 상위 팀이 공개한 분석에서 출발했습니다.
