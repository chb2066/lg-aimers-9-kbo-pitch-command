# KBO 투구 제구 성공 확률 예측

> **LG Aimers 9기 - KBO 투구 제구 예측**
>
> 주최: LG AI연구원 · 진행: DACON · 최종 2,403명 중 97위 (리더보드 1146.91)

투구 한 개가 제구에 성공했는지(`control_success`)를 확률로 예측합니다. 입력은 **그 공을 던지기 전까지 알 수 있는 정보만** 사용할 수 있습니다. 볼카운트, 주자, 점수 상황, 투수와 타자의 누적 기록 같은 것들이고, 실제 투구 위치나 판정 결과는 쓸 수 없습니다.

학습 데이터는 2019~2024 시즌 약 147만 구이고 평가는 공개되지 않은 2025 시즌 데이터로 진행됩니다. 점수는 Brier Skill Score에 100,000을 곱한 값입니다. 제출은 추론 코드와 모델을 zip으로 올리면 서버가 실행하는 방식이며, **평가 데이터의 각 행은 서로 독립적으로 예측**해야 합니다.

이 저장소는 최종 제출본을 만드는 학습 파이프라인 전체를 담고 있습니다. CPU만으로 동작합니다.

| 파일 | 역할 |
|---|---|
| [train.py](train.py) | 검증 예측부터 제출 zip 생성까지 전 과정 |
| [derive_target.py](derive_target.py) | 평균 보정값 계산 |
| [submission/](submission/) | 제출 zip에 들어간 추론 코드 |

설계 근거와 단계별 실험 기록은 저장소가 아니라 프로젝트 노트에 있습니다.
→ [시즌 경계를 넘는 투구 제구 예측](https://chb2066.github.io/projects/kbo-pitch-command/)

## 개요

`train.py`는 네 단계를 차례로 실행합니다.

- **시간순 검증 예측** (약 98분) - 각 fold가 그 시즌 이전 데이터만 학습하는 walk-forward OOF. 잔차 보정표의 재료가 됩니다
- **잔차 보정표 생성** - 검증 예측의 잔차를 구간별로 집계해 저장합니다. 정규시즌(`game_type == R`)만 사용합니다
- **최종 모델 학습** (약 71분) - 전체 학습 데이터로 회귀·분류 모델을 학습하고 시드 앙상블합니다
- **평균 보정과 행 독립성 검사** (약 5분) - 검사에 하나라도 걸리면 zip을 만들지 않습니다

행 독립성 검사는 같은 행을 한 개씩 넣거나, 순서를 섞거나, 성질이 정반대인 행 사이에 끼워 넣는 등 25가지 방식으로 입력해 결과가 완전히 같은지 확인합니다. 대회 규정이 요구하는 조건이자, 평가 데이터 안에서 통계를 내는 실수를 잡는 장치입니다.

보정에 쓰는 기준값은 전부 학습 데이터로 만들어 저장해 두고, 추론 시 각 행이 자기 값으로만 조회합니다.

## 설치

Python 3.11, CPU만 사용합니다. 아래 소요 시간은 12스레드 기준이고 메모리는 16GB 이상을 권장합니다.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 데이터

DACON 대회 페이지에서 받은 `train.csv`를 `data/` 폴더에 넣습니다. 대회 데이터는 재배포할 수 없어 저장소에 포함하지 않았습니다.

```
data/train.csv
```

주요 컬럼은 다음과 같습니다.

| 컬럼 | 설명 |
|---|---|
| `control_success` | 예측 대상. 제구 성공 여부 (0/1) |
| `game_type` | 경기 유형. `R`(정규시즌) / `F`(그 외) |
| 볼카운트·주자·점수 | 투구 시점의 경기 상황 |
| 투수·타자 누적 기록 | 그 투구 이전까지의 통산·시즌 기록 |

> 현재 투구의 위치, 판정, 구종, TrackMan 측정값은 사용하지 않습니다. 대회 규정상 투구 전에 알 수 없는 정보이기 때문입니다.

## 사용법

```bash
python derive_target.py     # 평균 보정값 계산. 약 30초, 0.48051 출력
python train.py             # 전체 학습. 약 3시간, output/submit.zip 생성
```

빠르게 확인만 하려면

```bash
python train.py --fast
```

회귀와 분류 모델을 하나씩만 학습합니다. 이전 실행의 잔차 보정표가 `output/`에 남아 있으면 재사용해 약 35분에 끝납니다.

| 옵션 | 설명 |
|---|---|
| `--fast` | 모델을 하나씩만 학습하고 기존 잔차 보정표를 재사용 |

## 폴더 구조

```
train.py             학습부터 제출 zip 생성까지
derive_target.py     평균 보정값 계산
requirements.txt     학습 환경 의존성
submission/          제출 zip에 들어간 추론 코드
  script.py            서버가 실행하는 진입점
  kbofeat.py           피처 생성
  feat_ext61.py        64피처 구성
  feat_anchored.py     기준값 고정 피처
  requirements.txt     제출 환경 의존성
```

`submission/`은 리더보드 1146.91점을 받은 제출 zip과 같은 코드라 주석도 당시 그대로 두었습니다. `submission/requirements.txt`는 초반 LightGBM 계열부터 이어 쓰던 목록이라 지금 코드가 쓰지 않는 패키지도 들어 있습니다.

## 대회 규정과 공개 범위

- 대회는 2026년 9월 2일에 끝났습니다. 규정 8-A의 코드 공유 제한은 대회 기간에 한정되고, 8-B는 대회 정보를 바탕으로 만든 소스 코드의 공개를 허용합니다.
- 규정 7-B에 따라 대회 데이터와 주최측 데이터 설명서는 포함하지 않았습니다.
- 대회 초반에는 운영진 질의응답을 근거로 평균 보정값을 제출 점수에서 역산해 쓰기도 했습니다. 8월 31일 보정 상수는 학습 데이터로 정하라는 안내가 나온 뒤로는 학습 데이터로만 계산했고, 최종 제출본의 값도 그렇게 구한 것입니다.
